# 이메일·전화 문의 방식 출시 설계

## 목적

Resend 계정과 API 키가 없는 현재 조건에서 실패하는 문의 폼을 공개하지 않고, 방문자가 확정된 이메일과 전화로 바로 문의할 수 있게 한다. 새 홈페이지를 검증한 뒤 Cloudflare Pages 운영 배포와 `jinsolpartners.com` 연결을 완료한다.

## 검토한 대안

1. **직접 이메일·전화 문의(채택)**: 유형별 안내와 `mailto:`, `tel:` 버튼을 제공한다. 별도 계정이나 서버 설정이 필요 없고 실패 지점이 가장 적다.
2. **메일 프로그램 연동 폼**: 입력값을 브라우저에서 메일 프로그램으로 넘긴다. 방문자 환경에 따라 메일 프로그램이 없거나 본문 전달이 실패할 수 있어 채택하지 않는다.
3. **Resend 서버 폼**: 자동 접수 경험은 좋지만 계정, API 키, 발신 도메인 인증이 필요하다. 추후 별도 작업으로 남긴다.

## 화면과 동작

- 연락 페이지의 세 구역과 기존 앵커 `#consulting`, `#small-business`, `#education`은 유지한다.
- 각 구역은 문의 시 알려줄 항목을 목록으로 안내하고, `이메일 보내기`와 `전화하기` 버튼을 제공한다.
- 이메일 버튼은 `greatysb@naver.com`을 수신자로 하고 문의 유형별 제목을 미리 채운다.
- 첫 상담 무료, 영업일 기준 1일 이내 답변 문구는 유지한다.
- 모바일 하단 문의 버튼은 이메일과 전화로 연결한다.

## 제거 범위

- 연락 페이지의 HTML 폼 세 개와 `assets/js/forms.js` 로딩을 제거한다.
- 사용되지 않는 `assets/js/forms.js`와 `functions/api/` 문의 API 파일을 배포물에서 제거한다.
- 홈페이지의 “문의 폼” 표현을 전화·이메일 표현으로 바꾼다.

## 개인정보 안내

- 홈페이지가 입력 폼으로 개인정보를 직접 수집하거나 저장하지 않는다고 명시한다.
- 전화·이메일 상담 과정에서 제공된 정보의 이용 목적과 상담 종료 후 6개월 보유 원칙은 유지한다.
- 사용하지 않는 폼·외부 메일 API·별도 데이터베이스 설명은 제거한다.

## 검증

- 변경 전 실패하는 정적 회귀 테스트로 폼과 API가 남아 있음을 확인한다.
- 변경 후 모든 문의 구역에 이메일·전화 링크가 있고, 폼·폼 스크립트·API 파일·“문의 폼” 문구가 없는지 검사한다.
- 기존 G4 릴리스 검수, 배포 미리보기의 주요 경로 HTTP 확인, GitHub PR 검사와 Cloudflare 운영 배포 상태를 다시 확인한다.
- 운영 도메인은 Pages 프로젝트에 등록하고 DNS·TLS·주요 페이지 응답을 검증한다.

## 범위 밖

- Resend 가입, 발신 도메인 인증, API 키 생성과 자동 문의 폼 복원은 이번 출시에 포함하지 않는다.
